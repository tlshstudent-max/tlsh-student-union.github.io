# 🏛️ 國立斗六高級中學學生會官方網站
> **「凝靜 · 凝聚 · 向心力」** — 打造校園中深邃且充滿質感的數位石澗。

## 開發與管理後台

網站提供免登入的公開資訊與 `/admin/` 幹部工作台。後台支援 Google 登入、管理員／編輯者授權、公告與文件草稿、預覽、發布、下架及修改紀錄；需先設定 Supabase 才能使用真實登入與儲存。

- 完整設定、資料搬移、測試及交接：[SETUP.md](SETUP.md)。
- 日常公告、活動、文件發布與草稿回復：[CONTENT-GUIDE.md](CONTENT-GUIDE.md)。
- 搜尋結果、分享圖片與外觀設定：[SEO.md](SEO.md)，含 GitHub Pages 子路徑與動態公告的搜尋限制。
- 第一次啟用免費後台：[START-HERE.md](START-HERE.md)，含單次初始化與第一位管理員設定。
- 本機開發：`npm ci`、`npm run build`、`npm run dev`。
- 自動驗證：`npm test`；瀏覽器流程：`npm run test:browser`。
- `site-config.js` 已設定 `publicDataSource: 'supabase'`。合併部署後，公告與文件從幹部後台發布，官網只讀取已發布內容；原試算表保留為搬移前備份。

## 🌊 計畫願景
本站由 **斗六高中學生會** 自主開發，旨在建立一個行政透明、美感並蓄的數位窗口。我們採用「禪意石澗」的視覺語彙，將各組業務模組化，確保行政資料的長久傳承與專業呈現。

## 🛠️ 技術架構
本專案採用純粹且高效的開發模式，確保在任何裝置上皆能展現穩定質感：
* **前端基底**：HTML5 / CSS3 (黑曜石深邃質感佈局)
* **動態渲染**：原生 JavaScript (暖金禪意光影追蹤)
* **內容管理**：Supabase 幹部後台（公告與文件草稿、發布及下架）
* **託管平台**：GitHub Pages

## 📂 石澗大樓構造
我們採取「分房隔離」的模組化架構，各部門擁有獨立裝潢與維護空間：
* `index.html`：**大廳** — 官網入口與最新動態中心。
* `president/`：**正副會長室** — 核心願景與意見回饋窗口。
* `activities/`：**校園活動** — 同步顯示發布位置為活動組的已發布公告與文件。
* `pr/`：**公關組** — 對外連結、資源爭取與特約商家資訊。
* `rights/`：**學權組** — 學生權益守護、法規查閱與申訴入口。
* `design/`：**美宣組** — 視覺美學實驗室與設計典藏。
* `docs/`：**文書組** — 行政檔案庫、會議紀錄與法規彙編。

## 💡 維護備忘錄

* **公告與文件更新**：從 [幹部工作台](https://tlshstudent-max.github.io/tlsh-student-union.github.io/admin/) 新增內容，先存草稿確認，再將狀態改為「已發布」。發布後重新整理官網即可讀取。
* **部門發布**：在「發布位置」選公關組、學權組等部門，可另外勾選是否列在首頁；類別不再決定新內容的發布位置。
* **會議紀錄**：按「新增會議紀錄」，直接輸入紀錄內文或貼上文件連結。已發布文件都會收錄在公開文件庫，之後可從原項目編輯更新。
* **緊急通告**：後台可設定台灣時間的結束時間，發布後顯示於全站頂端；可收合，更新後重新展開，到期自動移除提示並保留原公告。既有專案先執行 [003 緊急通告更新](supabase/migrations/003_urgent_notices.sql)，不需新增付費服務。
* **已有專案升級**：先在 Supabase 執行 [002 發布位置更新](supabase/migrations/002_publication_locations.sql)，再部署這次程式，保留原資料及權限。
* **成員授權**：管理員在工作台的「成員與權限」新增或停用幹部，並分配公告、文件及發布權限。
* **舊資料備份**：[原公開資料試算表](https://docs.google.com/spreadsheets/d/1SBd3jZVA38dv0TSuS-LyKIsSzmGWI9Zyo_7zH5pDNPU/edit) 保留作為搬移前備份，不會與後台雙向同步。
* **交接說明**：帳號、資料來源及驗收步驟見 [SETUP.md](SETUP.md)。
* **風格調整**：跨頁字級與互動放在 `ui.css`；讀取在其後的 `material.css` 集中材質、圓角及首頁構圖，背景底層由 `stone-surface.css` 共用，後台細節放在 `admin/admin.css`。`theme.css` 提供白色版，`theme.js` 在樣式載入前恢復使用者選擇，預設維持黑金版。最後的 `glass.css` 集中導覽／操作面板的毛玻璃、按鈕按壓及可及性替代樣式，意見回饋排版由 `president/feedback.css` 負責。各組的 `style.css` 保留必要的部門特色，避免重複定義共用元件。
